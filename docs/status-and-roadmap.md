# RepoHarness 当前阶段与后续路线

RepoHarness 是一个 verification-gated Coding Agent Harness 原型。
它已经具备：仓库概览、受约束搜索/读取、带乐观并发校验的多文件编辑、diff、受限测试执行、SQLite 运行事件、断点恢复、工具调用幂等、上下文压缩、完成门禁、MCP/API 接口，以及独立于模型自述的隐藏评测。

截至当前工作树，v1 有 14 个任务，v2 新增 8 个偏真实业务逻辑的多文件任务；还加入了 completion gate、read-before-write、context/tool-result compaction 的消融测试和过程失败分类。

## 距离真正 Coding Agent 的主要差距

1. **隔离不是安全边界**：现在主要依赖路径和命令白名单；下一步应使用每任务容器/沙箱、网络默认关闭、CPU/内存/磁盘/进程数限制，并记录策略拒绝。
2. **工作区生命周期不完整**：目前是目录复制；需要 git worktree、基线 commit、patch 导出、回滚、冲突处理和最终变更摘要。
3. **代码理解仍以文本为主**：需要符号索引、AST/LSP 跳转、引用关系和跨语言项目识别，减少“搜索命中但不理解调用链”。
4. **编辑协议不完整**：需要标准 unified patch、rename/delete、格式化器、冲突恢复和大文件分块编辑。
5. **评测外推性不足**：需要 held-out 任务、真实 issue 数据、污染检查、多模型/多温度重复，以及 patch quality 和回归率指标。
6. **生产运行能力不足**：需要 durable queue、租约、并发 worker、崩溃恢复、成本/延迟 trace、人工审批和权限等级。

## 建议的 v3 评测矩阵

### A. Agent 行为能力

- 多文件 API 迁移：修改实现、调用方、测试夹具，但不得改测试断言。
- 依赖/配置迁移：更新 manifest 和锁定配置，验证干净环境可安装/启动。
- 回归修复：可见测试通过但隐藏测试失败，要求读取文档并修复边界行为。
- 长上下文任务：加入无关目录、生成文件和大文档，测检索精度、token 和重复读取。

### B. Harness 可靠性

- stale patch / 部分失败批次：验证多文件编辑原子性和恢复行为。
- 中断恢复：在 mutation、verification、planner retry 三个位置注入崩溃，检查不重复写入。
- 恶意仓库：路径穿越、危险命令、测试文件篡改、隐藏产物和 symlink 边界。
- 零测试/假绿色：命令返回 0 但没有发现测试时必须拒绝作为验证证据。

### C. 结果指标

除了 pass rate，固定报告：首次修复后通过率、最终修复率、隐藏测试击穿率、测试篡改率、未验证完成率、工具失败率、重试恢复率、重复读取率、平均/尾部 token、耗时、每任务成本。
